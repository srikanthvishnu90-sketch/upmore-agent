# Verified native-text bridge checkpoint

The normal career entry now accepts genuine raw text through its real host
routing, derives canonical intent, projects owned host evidence into the frozen
journey-context contract, admits a generation/checker pair under existing cash
and monthly gates, and commits accepted advice plus the owned proposed turn
atomically. Tests submit exactly `{thread_id,turn_key,message}`. They never
translate user wording into typed interview commands. The existing typed
interview entry and B source remain unchanged.

Controlled native tests demonstrate original free-form advisory prose, multi-turn
project discussion/correction/hypothetical separation, fresh-session checked
draft revision, exact whitespace-preserving stored input and both complete
provider wires. The user wording, original-input hash, host-derived intent and
canonical context are durable before dispatch. The independent paid checker
binds the exact request, candidate, complete rendered reply, context, intent and
user-text hashes; the database checks that proof and the raw usage readbacks.
Paid checking is labelled `paired_gateway_budgeted/v1` and cannot be relabelled
as local. The grounded-v2 `local_no_external_calls` verifier contract is unchanged.

All **18 scoped native checks pass**: 13 raw-entry controls and five authority/
recovery controls. These include no-funding admission, rejected/misbound checking,
malformed usage, unknown holds, free exact replay, conflicting text/key rejection,
competing identical requests, save-fault recovery without redispatch, foreign/
client-role denial, pause and erasure between legs. A failed save followed by a
newer owner turn cannot overwrite newer memory on retry. Billing can settle
without allowing stale output publication or resurrecting erased private state.

Failure history is retained. The initial raw baseline was 0/13; one pause fixture
used an unsupported account-pause phrase. It was corrected to documented `STOP`
with an additional durable-paused assertion before implementation; that baseline
is 1/13. The first implementation was 12/13: the remaining SQL helper returned
trimmed display text, so the test now decodes JSON and also checks stored byte
length, retaining the exact original expectation. These are explicit fixture/
measurement errors, not passing runtime evidence. A later CASE-parentheses SQL
setup failure and its exact proposal remain. The independently frozen recovery
suite first passed 4/5 and exposed a real stale-snapshot overwrite; the original
claimed versions are now required at commit and all five pass. No failed run or
expected response was deleted or weakened.

The safe source suite passes 212/212 and the unchanged gateway/grounded-v2 suite
passes 84/84. Four stage/bundle checks pass. Native shared modules pass Deno
checking. Direct career-handler local typechecking passes with only the remote
Supabase client import replaced by an explicitly marked type-only stub because
this executor could not fetch that SDK; it is not a live SDK test. CI now adds
the actual career handler to its original real-SDK Deno checks. Dynamic pure-JS
host seams are annotated rather than suppressing type checks. No protected
writing fixtures were read in these local checks.

The full native SQL and exact-head CI results are tracked separately after this
checkpoint. Controlled provider responses validate plumbing and accounting,
**not actual model quality**. No paid call, production application, deployment,
external send/application, browser execution or allowance mutation occurred.
Muse owns final integration. The evaluator's allocation is untouched and its
sealed scenarios/private manifest were not read. Only generic invocation and
admission source contracts were inspected for interoperability.
