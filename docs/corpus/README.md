# Response-style corpus: eval results (offline)

Generated by `deno run -A evals/corpus/run.ts`; do not edit. Each corpus example (corpus/upmore-convo-corpus-N-of-5.txt) is replayed through the real flow router with the corpus's fictional world and graded by rules (evals/corpus/graders.cjs): a card before money, no success words without a recorded execution, the typed amounts and the handles on the card, one clarifying question when the example asks one, short replies.

- **PASS**: every rule held. **LIMITED**: an honest stop where the example shows a card (a standing owner rule such as the $5 live order cap, or a rail that is not live); nothing moved. **NOT_BUILT** / **DIVERGES**: a rule broke and evals/corpus/triage.json says why (the capability is not built yet, or the code deliberately departs from the example); labeled, never counted as a pass. **FAIL**: a rule broke with no written reason. **NEEDS_MODEL**: the chat model answers it; runs only live (`--live`), with the LLM judge.
- Offline proves the code paths, not the product: nothing here is a live or provider-confirmed result.
