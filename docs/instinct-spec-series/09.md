Upmore Spec 09: Investing Without Recommending"How can we program it to help it make more money via investments without recommending." This is the most legally sensitive doc in the series. The line it draws is the whole product: everything an agent can do to grow the user's investments that is information, execution, or education, and none of what crosses into regulated advice.GoalBuild src/investing/ with the advice guard as a load-bearing component, not a disclaimer footer: every investing response passes through it, and the categories below are enforced in code.The lineIn the US, personalized investment advice - telling a specific person what to buy, sell, or hold based on their situation - is regulated activity (investment adviser territory). A software agent that recommends securities to a user crosses it. An agent that provides information, tools, education, and user-directed execution does not. The boundary rule for every surface:Allowed: facts, math, mechanics, user-directed action, general education, user-defined criteria.Not allowed: unprompted "buy X", ranked picks framed as what the user should do, model portfolios presented as personal guidance, return promises, "this stock is undervalued for you."The test applied to every sentence: does this tell the user what to do with securities, or does it give them something true and let them decide? "NVDA is 22 percent of your portfolio" is information. "You should trim NVDA" is advice. The first ships; the second is blocked by the guard.This doc is a product specification, not legal advice. The boundary, the guard rules, and every disclosure get reviewed by US securities counsel before launch, and the guard's rule set updates from that review. Until that review exists, the conservative reading wins: when in doubt, the agent gives information and asks the user to decide.What the agent does (the full legal surface)Portfolio intelligenceINV-001 through INV-006: consolidated holdings across every brokerage and retirement account, allocation by asset class/sector/geography, concentration reporting, overlap with indexes, performance vs benchmark, dividend tracking and forecast.Concentration alerts (INV-003): "NVDA is 22 percent of your invested assets" is the flagship allowed nudge - factual, threshold-based, decision-free. The user asked for this exact class of help.Drift reporting: current allocation vs the target the user themselves set, stated as distance, with the rebalance math ready but never the instruction to do it.User-defined screeners and watchlistsINV-007: the user defines criteria (P/E under 20, revenue growth over 20 percent, sector, market cap); the agent runs the screen and reports matches as data. The criteria are the user's decision; the agent is the search engine.INV-008/009/010: watchlists with price, percent-move, and earnings alerts.The pattern that keeps this legal: the agent never originates the criteria. "Show me stocks like the ones I own" is answered by analyzing characteristics, not by issuing picks.User-directed executionINV-011/012: the user says "buy 10 shares of MSFT." The agent restates the order (ticker, shares, estimated cost, account, order type), gets confirmation (T3), executes through a broker-dealer partner rail (GATED: requires a partner such as Alpaca or DriveWealth plus the compliance setup in doc 14), verifies the fill, and receipts it.INV-013: recurring buys on a schedule the user sets (T4 inside an envelope).INV-014: rebalancing executed only on the user's explicit approval of a computed trade list.The agent never suggests the order. It makes the user's decision cheap to execute and impossible to fumble.Mechanics that make money without adviceINV-015: tax-loss harvesting candidates surfaced as math: "you hold $4,100 in unrealized losses in these lots; harvesting them offsets gains" - the user decides and directs.INV-016: wash sale checking on user-directed trades (a factual rule check that saves real money).INV-017: cost basis and realized gains reporting so tax decisions are informed.INV-018/019: contribution room tracking (IRA, 401k, HSA) and rollover status - the "did you know you have $7,000 of IRA room this year" nudge is contribution mechanics, not security advice, and it is some of the highest-value allowed alerting.INV-024 guard on all of the above.Education and contextExplainers on any concept, mechanics, or term, on request.News linkage (doc 10): "here is what happened with a company you own" is information."Investments that may be interesting" (the user's phrase): answered through the user's own screens and watchlists, through acquisition/IPO calendars (NEWS-006), and through thematic education - never through "you should buy."Private marketsINV-020: track the user's private holdings (the user holds SpaceX) with valuations from available marks, clearly labeled as estimates.INV-021: surface private deal flow and secondary market events (tender offers, secondary platforms) as information with access constraints stated. Execution is handoff-only: private securities transactions are paperwork-heavy and regulated; the agent prepares, the user and the platform execute.The advice guardsrc/investing/advice-guard.ts: a classifier plus rule layer that runs on every investing response before it sends. Rules: no imperative buy/sell/hold directed at the user; no ranked security picks framed as recommendations; no return predictions presented as expectations; every analytics statement carries its data source and as-of time; every screen result states the user-defined criteria that produced it. Red-team set in doc 12 tries to make the guard fail (jailbreak phrasings, "pretend you're my advisor", hypotheticals); the guard must hold.Standing disclosure, shown once per conversation when investing topics start, not plastered on every message: "I can show you data and execute what you decide. I don't give investment advice."Build packet for Claude CodeContext: src/investing/ with portfolio.ts, screens.ts, execution.ts (partner rail behind a fake for tests), harvest.ts, guard.ts, education.ts. Consumes holdings from doc 04 connectors. Uses doc 01 confirmation UX and doc 11 voice rules.Constraints: execution.ts never talks to a real broker in tests. The guard is a hard gate in the response pipeline, called in one place, not sprinkled.
