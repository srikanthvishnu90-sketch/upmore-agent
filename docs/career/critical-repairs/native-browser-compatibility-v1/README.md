## Reproduced defects and narrow repairs

1. **Pending research publication could be stranded by the pull supervisor.** Real PostgreSQL showed a claimed central intent with no result, one completed read effect, local `evidence_ready` plus `publicationPending:true`; the supervisor counted a terminal task and stopped. It now retains that same active checkpoint until publication is confirmed, including restart, and applies existing uncertainty/transition/time/private-retention bounds. Retries reuse the immutable capture; no reread or physical redispatch. Original frozen `pending-publication-*.log` files retain the failure. A second real-SQL failure exposed a pending-queue read before the retry; the service now recovers already-captured local publications before requesting new queue work. `f1adbb72` fixes that ordering and `ce810f30` verifies both legacy and persisted owned-worker identities. No scope, lease, or account fence was weakened.
2. **Owned physical effect admission used transaction-start time after an owner-lock wait.** A reserved effect's consume transaction started before a future lease deadline, actually waited for the owner advisory lock, and returned `consumed:true` after expiry. The trigger now checks `clock_timestamp()` at admission, including null lease and absolute intent expiry, and at completion. The same frozen regression now leaves the effect reserved and returns `task owned lease revoked`. No physical effect was executed in the probe; existing owner/version/epoch/pause/lease/approval/uniqueness fences remain.
3. **Unsafe filename metadata reached ordinary history.** A valid synthetic PDF whose filename matched the existing identity-redactor policy produced HTTP 200 and two ordinary history rows. The standalone ingress now rejects that metadata before any storage RPC. Source and real-SQL regressions cover synthetic SSN/password/OTP shapes and preserve an allowed phone-shaped filename and exact bytes. Private RPCs remain service-only; this is the authenticated ingress policy boundary.
4. **Encoded document dialects bypassed the declared bounded-plain gate.** Valid synthetic classic-xref PDF with escaped action names and UTF-16 DOCX parts containing DTD/template markers reached the actual ingress and local SQL with HTTP 200. PDF name escapes are decoded for inspection without rewriting originals or changing xref offsets; compressed-object dialects remain refused. XML/rels parts require fatal UTF-8 decoding, no NULs, and UTF-8/ASCII declarations. Existing size, expansion, CRC, archive-range and active-marker guards remain. This bounded policy is not antivirus or a general PDF/XML parser. UTF-16 documents are deliberately unsupported. The first fix rejected random malformed `#` bytes inside an otherwise valid compressed PDF stream; the existing idempotency test caught HTTP 400 instead of 409. `580be542` removes that overbroad rejection while retaining escaped action-name refusal, and the failed candidate log is preserved.
5. **Combined CI did not install browser SQL and omitted the new Edge entry.** Original shared bootstrap discovered the applicant store suite but lacked owned-claim/store/ingress DDL. A diagnostic with only test-selection widened failed 14/15 store cases on absent RPCs. Shared CI now installs the proposals in dependency order and checks `career-applicant/index.ts`. That entry's empty-default inference independently failed real-SDK Deno checking (`string[]` vs `never[]`); a type-only annotation fixes it with no suppression.

The service merge retained both imports (`validResearchPNG` and `validControlledReceipt`), both epoch cleanup protections, and scoped bounded polling plus pending-publication retries.
