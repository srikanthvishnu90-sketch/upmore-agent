## 4. Quality bar and process
- **The strict standard** (`docs/architect/STRICT-STANDARD.md`), applied to every PR:
  1. Tests assert real outcomes in state (DB rows, events, outbox deliveries, external requests with exact
     params), and that the reply is true to that state.
  2. Fail-first, shown.
  3. Every guard mutation-checked: break it, and a test goes red.
  4. Adversarial cases.
  5. No "environment" or "pre-existing" excuse without reproducing it on the base.
  6. No invented numbers.
  7. Plain user words, no internal codes.
  8. Channel parity across Telegram, web and SMS, or say plainly what is missing.
  9. Precise reports.
  10. A hostile self-review before reporting.
- **Product first** (2026-10-26 16:12; `docs/architect/PRODUCT-DIRECTIVE-2026-10-26.md`). Only the product's capabilities matter now. Get every capability to 5/5,
  meaning every link of trigger → asks → connectors/keys → execution → recorded outcome → truthful reply →
  failure paths → follow-through is present and outcome-tested on every channel. Work outside the product
  (growth, verification paperwork) finishes but does not expand.
- **Next milestone:** the owner has Instinct test about 1,000 brand-new-user scenarios trying to complete real
  tasks. "Ready for Instinct" is the bar defined in the E2E completeness doc (section 7).
- **Merging:**
  - CI green on the exact head. Required jobs: `gate (core)`, `gate (browser)`, `gate (architect)`,
    `gate (forms-ci coverage)`, `database`.
  - An independent review (someone who did not write it) returns APPROVE.
  - Merge sha-guarded: `gh api -X PUT repos/.../pulls/N/merge -f merge_method=merge -f sha=<head>`.
  - Merge one at a time. If PRs are stacked, merge the base first; a later PR's head must contain trunk.
  - A fix needed by a whole chain goes on the earliest PR, then is merged down the chain.
- **CI:** `ci.yml` runs once per PR head (concurrency cancels superseded runs). Pushes run CI only on trunk.
