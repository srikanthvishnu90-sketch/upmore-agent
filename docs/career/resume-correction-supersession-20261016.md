## Narrow source-authority repair

The only product source edited is `packages/domain/130-career-onboarding.js`.
Both router bundles are regenerated by the official generator and verified to
contain only the module-130 replacement relative to the base.

- A direct correction instruction may apply one unambiguous explicit source to
  confirmed dates as well as unresolved conflicts. The existing source aliases
  `resume-new.txt`, `new`, `newText` in `resumeTexts` / `resumeSources` are retained.
  Explicit source text wins over historical embedded labels. Missing, empty,
  non-text or conflicting supplied sources never fall back to those labels.
- Repeated updates preserve fact identity, write the actual prior active value
  into the audit, advance `fact_version` once per actual fact write and rebuild
  dependent state. There is one active resolution annotation; previous values
  remain traceable in the audit. A fresh **2030** source can supersede **2033**:
  numeric year order is not used as a freshness signal.
- Every target is planned before any fact is mutated. Multiple graduation dates,
  multiple education targets, multiple organization/date ranges, or one
  organization/date pair matching two jobs are refused without partial writes.
- Adopted explicit source fingerprints are kept only in the existing owned
  profile's correction audit/resume-source record. SHA-256 reuses existing Node
  crypto or the already-bundled 141 helper. No raw source text is added to the
  audit, and no global identity/hash/correction store is created. The actual
  staged bundle's digest is checked against Node's digest.
- Re-delivering the current source is a no-op for facts, audit and fact version.
  Previously adopted, superseded source bytes cannot acquire authority again
  through the generic new-resume command. Failed commits cannot mark a source
  adopted. Erasure removes this profile-owned history; an explicitly reimported
  source in a new epoch starts a fresh owned history.
- Embedded labels remain a first-conflict compatibility path only. They cannot
  become authoritative again after a correction history exists. Quoted,
  hypothetical or conditional text is not a direct correction instruction.
- Legacy export/import/replay APIs remain inert. The host, handler, ownership
  checks, SQL schema, transaction, revision and privacy-epoch fences are unchanged.

A new explicit source is supplied through the verified owner's existing saved
context, not through a new request-body authority override. Direct domain
callers remain responsible for supplying that owner's context; this patch adds
no authentication bypass or new upload/ingestion API.

## Limits and handoff

Source hashes identify previously adopted bytes within one saved profile; they
do not establish when a previously unseen document was authored or prove its
claims. The first legacy embedded-only correction has no source bytes to hash.
This bounded parser supports the existing graduation-year and organization/date
range paths, not arbitrary resume ingestion or general date inference. Multiple
education records require clarification rather than a guessed target. A special
intentional-reversion workflow for previously superseded files is not added.

Historical embedded source labels are retained as labelled provenance; the
current value is in the profile constraint/resolution and the one active
annotation. This does not audit or repair historic profiles beyond the explicit
owned correction requested, or change unrelated downstream resume rendering.

No deployment, credential configuration, paid/model/provider call, browser task,
external send, production migration or shared-branch merge occurred. The earlier
superseded candidate was preserved, not republished; no pending approval was
bypassed. Native Deno is unavailable, so native Deno checks are not claimed.
Gateway work remains on its existing separate review branch. The inherited C37
failures and broader release gates remain with Muse.
