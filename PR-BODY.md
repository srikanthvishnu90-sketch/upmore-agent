# MUSE-F-014 — cross-profile contamination: PR #90's correction-privacy fix ported to the candidate

**Failure (MUSE-F-014, P0).** Module 130 kept a process-global correction store keyed by email || name || profile.id || first fact id — and every profile shares id `profile-1` with fact ids restarting at F-001, so profiles collide in the store. Corrections were written into it (130:267) and replayed into whatever profile loaded next (130:557 → applyPersistedCorrections), overwriting that profile's graduationDate: correcting profile A changed profile B's graduation year from 2031 to 2028 in B's own recall. PR #90 (commit 11036192) fixed this on its own line but never reached the candidate build — this PR is that exact fix, ported: the store is deleted (corrections persist only in the owner's own atomic snapshot; the store functions become no-op stubs), plus its guard test, fixture, and call-site updates.

**What this PR carries** — the cherry-picked fix commit (source `packages/domain/130-career-onboarding.js`, guard `tests/correction-authority-privacy.test.cjs` + `tests/helpers/correction-privacy-fixture.cjs`, call-site updates in `tests/career-gauntlet-r2a.test.cjs`, `tests/career-gauntlet-r3.test.cjs`, `scripts/career/gauntlet/run-deepdive.cjs`, `run-rerun.cjs`) with the two bundle files regenerated by `python3 scripts/build-router-core.py` in both modes (the cherry-pick's own bundle hunks conflicted and were dropped, never hand-edited; `CORRECTION_STORE` occurrences in each built bundle: 6 → 0; both `--check` modes verify).
