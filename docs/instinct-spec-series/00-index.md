Sources: Claude Code best practices (code.claude.com/docs/en/best-practices) and Codex best practices plus the AGENTS.md guide (developers.openai.com/codex/learn/best-practices, developers.openai.com/codex/guides/agents-md). The short version, applied here:One packet per session. Each doc ends in build packets. Paste one packet into a fresh session, not three. Context window is the scarce resource; a focused session with a clean window beats a long session with accumulated corrections.Every packet answers four things up front, in Codex's prompt pattern: Goal (what to build), Context (which files and docs matter), Constraints (standards and do-not rules), Done when (what must be true). Never make the agent guess these.Every packet ends with a check the agent can run itself. Anthropic's core finding: an agent that can run a pass/fail check closes its own loop; without one, you are the verification loop. Each packet names the exact command (test suite, typecheck, script, screenshot diff) and requires the agent to show the output as evidence, not assert success.Specs are self-contained. Anthropic's interview-then-spec pattern: a good spec names the files and interfaces involved, states what is out of scope, and ends with an end-to-end verification step. Every packet here does that.Plan before code on anything multi-file. Start sessions in plan mode, approve the plan, then let it implement. For single-file clear fixes, skip the plan.Keep a root CLAUDE.md / AGENTS.md and let it earn every line. Anthropic and OpenAI both warn that bloated instruction files get ignored. Put only what the agent cannot derive from the code: commands, conventions, do-not rules, how to verify. A starter is below. When the agent makes the same mistake twice, add one line, not ten.Use the Writer/Reviewer loop for anything that touches money: one session builds, a fresh session reviews the diff against the packet's constraints, the first session fixes. Fresh context catches what the writer is blind to.Deterministic rules go in hooks, not prose. If a check must always run (typecheck after edits, no writes to the ledger without a test), make it a hook, because instructions in files are advisory and hooks are guaranteed.Starter CLAUDE.md / AGENTS.md for the Upmore repoThis is the entire file. Resist adding to it.# Upmore
## Commands
- Install: pnpm install
- Test: pnpm test (single file: pnpm vitest run <path>)
- Typecheck: pnpm typecheck (run after every change)
- Lint: pnpm lint
- Evals: pnpm eval (see docs/13-testing-harness.md)
## Rules
- Money movement code paths require a human review before merge, no exceptions.
- Never fake a connector: if a rail is not live, the capability returns NOT_WIRED. See docs/14-compliance-gating.md.
- Every user-facing money statement must cite its data source and as-of time.
- Capability registry (src/capabilities/registry.ts) is the source of truth; new features register there first with a status.
- Advice boundary: src/investing/advice-guard.ts runs on every investing response. Do not bypass it.
