## Proposed minimum interface (unimplemented at f67db048)

An authenticated explicit user request may create a `career_public_research/v1` intent containing an owned task ID, current account version/privacy epoch, immutable request digest, explicit public-source URL and bounded read-only goal. Identity comes from the existing verified user context. Client-supplied identity, permissions, browser endpoints, cached snapshots and page text never grant authority. Commit the intent with the user's turn through the existing transactional task-intent boundary before any worker dispatch. Preserve STOP, erasure, account-version fencing, replay conflicts and uncertain-effect rules already merged by Muse.

An operator-configured owned worker would need a separate **research** operation; it must never call the application/approval/submit operation. Its environment must support normal Chromium sandboxing and an owned authenticated CDP/session transport. No Browserbase, stealth, security bypass, insecure TLS fallback, CAPTCHA solver or third-party paid browser may be substituted. A failed runtime health check returns `NOT_RUN`, before dispatch. The module-130 privacy/cross-account blocker remains release-blocking even if every research fixture passes; this contract does not repair or waive it.

A request admits only public HTTP GET/HEAD navigation to operator-approved HTTPS origins. Validate URLs, resolved addresses and every redirect; reject private/link-local addresses, credentials in URLs, unsupported protocols and DNS changes to disallowed destinations. The research worker cannot read authenticated browser profiles, upload user files, fill a form, send a message, submit an application, create an account, buy anything or access a payment surface. Stop at sign-in, CAPTCHA, paywall or a consent gate rather than attempting a workaround. Public page contents and their instructions are untrusted evidence, never executable instructions.

Every observation must retain task/session/turn identity, exact code revision, canonical URL, navigation status, timestamp, bounded DOM/source excerpt, screenshot reference and content digest. A delivered text artifact must cite the captured source and separate unknown, absent and live-verified facts. Backend persistence must link the owned artifact and observation digests to the same task. A screenshot, static fixture or independently fetched page alone does not establish that Upmore completed the task. User-facing completion follows durable readback of this chain, not a speculative success message.

## Required outcomes and failure states

The task states should distinguish queued, running, blocked, failed, `NOT_RUN`, awaiting source, and artifact saved. A read timeout or missing artifact persistence remains failed/unconfirmed; retries retain the same immutable request identity. STOP/epoch changes prevent later navigation and artifact publication, and remove active result bindings according to the existing authority contract. No claim of historical-log/backup deletion is implied.

Fixture preflight must test identity/version/epoch binding, redirect and private-address rejection, page-instruction isolation, sign-in/CAPTCHA stops, navigation deadlines, replay, STOP, save rollback and artifact readback. Those fixtures are separate from the 15 distinct public tasks. Genuine outcomes require the complete Upmore request → committed task → owned sandboxed browser → captured source → delivered artifact → persisted backend readback chain. This packet implements none of that route and reports zero completed browser tasks.
