# Finisher bugs — Lane D1 (SC-121..SC-140, Track & Follow-Up)

All bugs found by replay tests in `tests/career-track-d1.test.cjs` (written and run BEFORE each fix; 8/8 failed pre-fix) in module `packages/domain/126-career-track.js`. Router bundle rebuilt after the module changes.

- BUG-D1-01 (SC-125): `classifyMessage` matched `recruiter_other` only against subject/body, never the sender — a genuinely ambiguous reply from a `recruiter@…` address classified `unknown`/no-signal and got no response draft. Fix: recruiter sender address also matches `recruiter_other`; added approval-gated `draftRecruiterReply` (sends:false).
- BUG-D1-02 (SC-126): OA ingest never set a deadline — `handleAssessment` returned `deadline: null` unless one was pre-stored, so "deadline set" was untrue for a fresh OA email. Fix: `extractMessageDate` parses the message's explicit date ("October 18, 2026"/ISO) into `assessment_deadline` on ingest; assessment record now carries `prep_pack_queued: true`.
- BUG-D1-03 (SC-127): Offer ingest moved the stage but started no intake and no expiry clock — `offer_deadline` stayed null even when the letter stated a respond-by date, so `offerCountdown` returned `days_left: null` while the alert claimed "Deadline tracking is on." Fix: same date extraction sets `offer_deadline`; ingest returns `offer_intake {started, expiry_clock_started}`.
- BUG-D1-04 (SC-129): `draftThankYou` ignored the user's one-line note entirely. Fix: `opts.note` is carried verbatim into the body and `basis.user_note`.
- BUG-D1-05 (SC-131): No daily digest existed (only `weeklyDigest`). Fix: `dailyDigest` — same log math over a 24h window with next actions.
- BUG-D1-06 (SC-132): Funnel analytics reported per-version rates but nothing could name/kill the losing variant. Fix: `resumeVersionVerdict` — kills only a version with ≥3 rows whose response rate is really lowest (fin-v1 0.25/4 in the TEST log); log rows are kept.
- BUG-D1-07 (SC-134): `offerCountdown` only produced 7/3/1-day alerts — no daily escalation for an imminent expiry. Fix: `offerEscalation` — inside 5 days, a dated daily schedule through the deadline, `stops_when: user_decides`.
- BUG-D1-08 (SC-139): `quietReport` covered only Submitted/Confirmed/Recruiter screen — an application silent 30 days after a **Final** round was invisible to the ghost rule and could never be labeled Ghosted. Fix: `Final` added to the quiet stages; added `ghostedOptions` (label + 3 options).
- NOT-D1 (verified pre-existing, not fixed here): `tests/mutation-report.test.cjs` fails 2 tests on the clean `pivot/career` baseline too ("docs/depth/MUTATION-COVERAGE.md is stale") — these are the only 2 failures in a full `node --test tests/*.cjs` run in this worktree (2703/2705); the career subset is 319/319 and agent100 is 103/103.
- BUG-D1-09 (SC-139, found by the scenario run after BUG-D1-08's fix): `ghostedOptions` computed `days_quiet` via `lastSignalAt`, which counts the system's own just-written `ghosted` event — so after `markGhosted` it reported 0 days quiet (scenario finished LEARN). Replay assertion added, then fix: the quiet clock in `ghostedOptions` runs from the last external signal, excluding `ghosted` events. SC-139 re-run: COMPLETE.
