## Rules
- Everything is LIVE (owner, standing since 2026-10-11): no paper trading, paper accounts, paper labels or paper fallback anywhere. Trades run only in the person's own live brokerage account, behind a fresh approval and the $5 per-order cap until the owner raises it in writing. Mocks exist only inside tests and are labeled mock.
- Money paths stay gated. No provider adapter, migration push to the live project, deploy, or production credential without the owner doing it himself.
- Docs follow the code: any session that finds docs-vs-code drift (a playbook, spec, BUILD-STATUS or README claim the repo or the live project contradicts) fixes the doc in the same commit as the finding and logs it in `docs/playbook-drift-<date>.md` (what the doc said, what is true, the source). Owner rule, 2026-10-11.
- A live failure is a test: every FAIL from a live gauntlet run is recorded by `evals/gauntlet/record-replays.cjs` and replayed by `tests/edge/live-replays.test.ts`; it stays red until fixed or triaged in writing (precondition, not_built, grader). Merge to main only after the live gauntlet passes on the exact commit.
- Never fake a connector or outcome: a rail that is not live returns NOT_WIRED; a cancel is done when the merchant's record says cancelled; a fee is recovered when the credit posts.
- Every user-facing money statement cites its data source and as-of time. The model explains numbers; functions over real rows produce them.
- `packages/capabilities/registry.json` is the source of truth. Status rises only via `status-overlay.json` with a `test_ref` that exists and passes.
- One owner per file (BUILD-STATUS "Claimed files"). Claim before editing; never edit the other agent's files, leave a Request instead.
- Never store OTPs, passwords or identity digits. One explicit approval per cancellation. No phone calls. No securities advice.
- Secrets never travel through chat (owner, 2026-10-11; decision 1 settled): anything sensitive (a card, an API key) goes on a secure link into the encrypted vault and is only ever used to fill the exact field it is for; it never appears in messages, logs, or anything the agent can read back. No password storage anywhere: a login is the person signing in themselves in a live browser window, completing their own 2FA; only the encrypted session persists (auth method LIVE_SESSION). The agent never asks for a password, code or card in chat.
- Prediction markets and crypto stay off until the owner decides in writing (decision 2; the gambling and crypto guards stand). Kalshi and Polymarket, standing rule (owner, 2026-10-11): never encourage a decision; anything said or done there rests on numbers only (prices, implied odds, fees, the person's P&L).
- Real company icons only (owner, must rule, 2026-10-11): every company Upmore shows (a connector, a merchant, a bank, a broker) is shown with its real logo, never a generic glyph, a letter tile, an emoji or a look-alike. Each logo file names its source and license (`img/brands/SOURCES.md`); a company without a real logo on file gets plain words until one is added.
- Connecting something always uses the owner's reference design: one short line saying what did not happen and "here's the link", then the connect link alone on its own line. iMessage draws it as the card (dark grey, the company's real logo centered with the Upmore wordmark centered right below it in Upmore green (#2E9E6B) in Libre Baskerville, a finance-style serif, then a dark grey strip with "Connect X to Upmore" and the domain), and the app draws the same card from the same image. Only providers a person can actually connect get a card.
- Automations are per-person toggles (owner, 2026-10-11 night): recurring or automatic investing, copying a portfolio or filing, reinvesting, sweeps and similar may exist, but each person turns one on themselves after it is restated in exact terms (what, how much, how often, from which account), and one message turns it off. Until the owner says otherwise in writing, every run still asks that person for a one-line yes before any order, and every order stays under the $5 cap; the loop's envelope autonomy stays off (`envelope_autonomy` is never set in shipped code). The agent offers, it never decides: before a trial bills it asks "should I cancel this for you?" and cancels only on that person's yes (one explicit approval per cancellation stands).
