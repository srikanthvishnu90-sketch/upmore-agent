# 1v1: Trainee vs the architect's gold replies (2026-11-01)

Owner, 2026-11-01: "theres alot wrong with the way it outputs info, sends poor information, doesnt act the way an iMessage bot should in terms of response, design... generate a 1v1 comparison between yourself and trainee, and try to get trainee to respond the same as you while providing links the same way as Instinct."

120 first-week scenarios (`evals/career/one-v-one/scenarios.ts`) across every feature, each with a channel (iMessage, SMS, WhatsApp, Telegram, web) and an account state (new, profile on file, tasks in flight). The gold reply for each was written by hand by the architect (Claude, in session; no model call, no Anthropic API spend). Every scenario carries a rubric a script checks (`score.ts`): bubble count and length, markdown, links present / alone on their own line after the line that says what they are / only real links, question count, numbered options, required facts, forbidden claims, and voice (filler, banned phrases, emoji, internal jargon). The link and formatting rules follow the owner's requirement docs Q73-Q95, Q581-Q587 and Q632-Q633 (cited by number only).

Trainee's side: trunk's live path in-process (`run.ts`): the scenario's state seeded, prior turns run, then the turn through the handler's code-first turns and the router (`evals/career/world.ts`), rendered by each channel's own adapter (`channel_registry.ts`). `CAREER_TEXTING_NATIVE` off is what ships by default; on is the texting voice the owner can switch on. Free, deterministic: `deno run -A --no-check evals/career/one-v-one/run.ts --label <label>`.

## What this branch changed (each with a fail-first test in `tests/architect/one-v-one-texting.test.ts`)

1. Links: a link inside a sentence now goes on its own line right after the sentence that names it (`channel_voice.ts` linksOnOwnLine reads a line sentence by sentence, never splitting open bold, italics or code). Before, the three postings' sentences came first and their three links after, so no link sat under its posting.
2. Numbered roles: the router's search list numbers its roles 1), 2), 3) (`142-career-router.js` roleSentence; ")" because the composer reads "1." as a sentence end), so the person can answer with a digit.
3. Bubble length: on iMessage and SMS a reply is split between paragraphs, lines and sentences into bubbles of at most 320 characters (a single sentence longer than that stays whole, in the 700-character bubbles as before) (`channel_voice.ts` imessageNativeRender).
4. Dates: texting channels show "Oct 19, 2026", never 2026-10-19; links and code untouched (`channel_voice.ts` humanDates).
5. Staged brain: on a texting channel the system prompt carries the texting rules (`prompt.ts` textingRulesFor), and the channel reaches it (`career_brain.ts` channel, one line in `handler-career.ts`, `world.ts`). Web and no-channel prompts are byte-identical to before.

Fixes 1, 3 and 4 are in the texting voice, which ships only with `CAREER_TEXTING_NATIVE=on` (an owner secret; off keeps the delivery tests' "unchanged" contract). Fix 5 matters only with `CAREER_BRAIN=staged`. Fix 2 is live on every path. (A crisis-phrase change was taken out on review: #354 owns the shared detector; V120 is left to it.) No reply prose was added to make a check pass; the words stay the router's or the model's.
