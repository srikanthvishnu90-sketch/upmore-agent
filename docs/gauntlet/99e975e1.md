## Named defect found by the composition probe (NOT a merge artifact)

**Lane A's named-role target parser over-captures the company name when
a capitalized sentence follows it in the same message.** In
`namedRoleTargetOf` (`packages/domain/142-career-router.js`, ~line
7972), the company capture's token class admits `.` and up to three
further capitalized tokens, so "…role at Northwind Ledger. The posting
is on Greenhouse. Please handle the application for me." parses the
company as **"Northwind Ledger. The"**; the pool lookup then misses and
the user gets the false "not in the served list" stop for a role the
pool DOES hold (probe S1b; same with the owner's live phrasing "…role
at Gusto. The posting is on Greenhouse. Please handle the application
for me."). The minimal frame (nothing after the company) resolves
correctly (S1a).

Disposition, with evidence: the defect **reproduces identically on
Lane A's standalone tree** (`work/conversation-depth-v2` @ e10a6a49,
same ask + the posting in the pool → same false stop; minimal frame →
`career_batch_apply`). No merge created or worsened it — Lane A's
guards assert the stop against an EMPTY pool, where the stop is correct
either way, so the shape was never exercised against a populated pool
until this probe. The composition is faithful; all four merges stand.
Fix belongs to the follow-up lane (Crew A allocation): tighten the
company capture at sentence boundaries + a fail-first guard (S1b's ask
against a populated pool). BUG/FR numbers: PENDING-ALLOCATION request
to Crew A — this lane does not self-allocate.
